    One glyph, one meaning¶

    There is no ISO standard for board-game glyphs. There is a shared visual accent, though, and you can see it if you look across the public icon sets game builders reach for: draw a card, discard a card, exhaust a token, spend a resource, gain a resource, pass a turn, reveal hidden information, start a timer. The shapes are not identical, but the meanings have converged enough that a player can usually tell what family of action they are looking at.

    That is useful source material. It is not a vocabulary.

    This project needed a vocabulary: a closed set where one meaning binds to one glyph, and the binding stays the same across every game. A currency glyph that means "money value in icon-only contexts" cannot also mean "score" on a later screen. A hidden-information glyph cannot become a connection-loss glyph because the silhouette happened to be convenient. The whole point is that the player learns the shape once, then the project keeps its promise.

    The industry sources are references, not inputs¶

    The obvious places to look are good ones. Kenney publishes Board Game Icons under Creative Commons CC0. game-icons.net is a large game-icon catalog under CC BY 3.0, which means attribution is required. Nieobie's Game Icon Pack is also CC0.

    Those libraries answer a different question than this project has to answer. They are broad collections of useful art. They show where the industry has settled on familiar metaphors: cards, coins, chips, arrows, eyes, clocks, warning triangles, check marks. They also carry different licenses, attribution rules, dimensions, stroke weights, and visual assumptions.

    So the rule here is deliberately narrow: treat those sources as semantic references, then draw our own original monochrome silhouettes.

    That buys three things.

    First, there is no third-party attribution burden in the product UI. That does not mean attribution is bad; it means a live game table is the wrong place to hide a legal dependency in every icon.

    Second, every glyph is authored directly into the project's contract: a 24x24 inline SVG path rendered as currentColor. The code does not adapt a vendored asset into the system. The registry owns the exact geometry the runtime uses.

    Third, the shapes are tuned for the actual screen they have to survive. This is a 10-foot TABLE interface, not a printed rulebook. A glyph has to hold up as a solid silhouette at small sizes, on a TV, from across the room.

    The vocabulary is closed¶

    The contract lives in docs/client/UI_DESIGN_METHODOLOGY.md, and the machine-readable registry lives in client/src/lib/icons/glossary.json. It follows the same discipline as codemap/vocabulary.json: do not invent a nearby token because it feels convenient. Use the registered one, or make the case that the vocabulary needs a new entry.

    There are two tiers:

    • core is for meanings shared across stages, shell screens, games, and review rules.
    • game is for game-local meanings, such as a Battleland combat statistic or a suit/resource marker. A game glyph still registers its meaning so it cannot collide with the core tier.

    Each entry records a name, tier, meaning, accessibility label, allowed surfaces, the inline SVG path, and a never_means list. That last field matters. It is a guardrail for adjacent semantics: if currency says it never means wager, then a future chip-stack screen cannot quietly reuse the money glyph because the two concepts are both financial.

    The result is stricter than an icon folder. It is a semantic table with art attached.

    Acceptance is split between tests and review¶

    Every glyph entering the registry has to pass seven checks from the glyph acceptance checklist:

    1. It reads as a solid monochrome silhouette at 24px.
    2. It stays distinguishable from every registered glyph at TABLE distance.
    3. It works in one currentColor; color can reinforce meaning but cannot define it.
    4. It contains no text, except the closed $ and D exceptions.
    5. It does not collide with existing silhouettes or never_means guards.
    6. A second meaning requires a second glyph.
    7. It is centered in a square viewBox and survives 44px touch-target padding.

    The project splits that list on purpose. Deterministic checks become the floor: field hygiene, no arbitrary text, crop safety, and registry shape are enforced by lint-icon-vocabulary. Visual judgment stays with review: silhouette, 10-foot distinctness, monochrome-first legibility, uniqueness, and the one-meaning rule.

    That split is the normal pattern here. Automation owns the checks it can prove. Review owns the human judgment and has to say it out loud.

    The core catalog today¶

    The current core tier in client/src/lib/icons/glossary.json contains these cross-game meanings:

    Glyph name Meaning
    currency Money value in icon-only contexts.
    wager Chips committed to a pot or bet.
    turn-marker Whose turn it is.
    dealer-marker Poker-convention dealer button.
    timer Time remaining.
    hidden Private or face-down information.
    revealed Public or face-up information.
    score Points.
    eliminated Out of the round or game.
    ready Player ready or confirmed.
    warning Destructive or irreversible referee action.
    connection-lost Seat presence problem.

    The registry also contains game-tier Battleland glyphs. Those are deliberately not listed as core because their meanings are local to that game. They still live in the same registry so review can catch collisions before a local symbol teaches the wrong lesson.

    Format beats icon beats word¶

    The vocabulary is not a license to put icons everywhere. The no-redundant-label rule is stricter than that: format beats icon beats word. $1480 already says "money" because the $ carries the category. A card face already says "card." A value under a player's avatar usually already says "that player's value." Only after format and position fail should a registered glyph carry the meaning; only after the glyph still leaves ambiguity should a word label appear.

    That is the point of a closed vocabulary. It is not decoration. It is a promise that when a glyph appears, it means exactly one thing.
